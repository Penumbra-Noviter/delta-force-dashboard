## 一、背景与目标

用户希望在自己的手机（小米 13 Pro）上使用 Delta Force Dashboard，约束：

1. 基本功能不变（记账 + 多账号为核心；**新增密码门板块**，见 §五）；
2. 两端数据可同步；
3. 手机 App UI 去 AI 味（清爽现代记账风）。

**密码门板块的动机**：局内（游戏中）不能频繁切屏看电脑其它应用，手机瞄一眼即可读当日各图密码门密码——这是手机端特性化、区别于电脑应用的功能。经确认**同时加入桌面端**，作为独立于记账、利润外的第三个模块（电脑端浏览完整、手机端局内速查，两端同一数据源）。

经设计讨论（2026-08-13，grill-me 七问 + 打磨 P1~P7 + 字体动效 D1~D3 + 落地风险调研 + 密码门板块 Q1~Q4）定稿如下。

## 二、形态与架构

- **桌面端**：内嵌 HTTP 服务（Python stdlib `http.server`，零新依赖），只读 JSON API + PWA 静态资源；随应用启动默认开启；侧边栏新增「手机连接」面板；**新增第三个业务模块「密码门」**（见 §五）。
- **手机端**：PWA（Vanilla JS ESM，符合项目技术栈倾向），浏览器访问 `http://<桌面IP>:<端口>/`，零安装；可"添加到主屏幕"（浏览器模式快捷方式，非完整离线安装）。
- **开发路线**：先 PWA 打通全链路验证体验；原生化（Flutter/Kotlin）留作二期候选，不做预埋。

**为什么不是 PySide6 移植**：桌面端是 Windows 专属（QLocalServer 单实例、`ctypes.windll` DPI、`Microsoft YaHei` 字体、路径约定），且 UI 全部桌面布局硬编码（最小 680×650、侧栏 130px、表格 7 列 ≥515px）；PySide6 Android 移植成本 ≈ 重写且 APK 超 100MB。PWA 路线桌面端零负担、手机端零安装、同步天然同源。

## 三、连接与授权

**流程**：

1. 桌面端「手机连接」面板显示 `IP:端口`（大字可复制）+「扫码连接」按钮。
2. 点「扫码连接」→ 桌面端用系统浏览器打开本地 `http://127.0.0.1:<端口>/connect` 页 → 页面用浏览器端 JS 生成二维码（**不引入 Python 二维码依赖**）。
3. 手机相机扫码 → 打开 `http://<桌面IP>:<端口>/`（二维码**只含 IP:端口**，不含任何 token/设备标识——URL 全程无敏感信息）。
4. PWA 首次运行生成 `device_id`（UUID）存 IndexedDB；请求携带 `device_id`。
5. 桌面端收到未知 `device_id` → 弹窗「设备请求连接，允许？」→ 允许后 `device_id` 写入白名单；拒绝后该设备 **30 秒静默**不再重复弹窗（防骚扰）。
6. 白名单内设备此后免授权直连。

**面板元素**（极简，无设备列表）：

- `IP:端口` 大字可复制；
- 「扫码连接」按钮（开 connect 页）；
- 底部小字按钮「清除已授权设备」——点击后全部已授权设备失效，任何手机都需重新扫码授权（替代设备管理列表）。

**IP 变化**：

- 手机端连接失败 → 明确提示「桌面端地址可能已变，请重新扫码」；
- 桌面端启动时若本机局域网 IP 与上次不同 → 「手机连接」面板提醒重新扫码。

**启动时端口策略**：检测端口占用，被占则自动换端口，面板显示实际端口。

**安全边界**：

- 白名单外请求一律 401，不泄露任何数据；响应不加服务器指纹头；
- API 仅只读端点 + 静态文件白名单目录 + 路径规范化（防 `../` 穿越，stdlib `http.server` 不自动防，**安全红线**）；
- 只读 API = CSRF/写破坏面为零（架构红利，非功能限制）；
- 局域网明文传输 + `device_id` 可被嗅探/伪装：家庭可信网络（WPA2/3 + 白名单）默认可接受，文档注明「公共网络勿用」；自签 HTTPS 留二期；
- 服务访问日志：轻量（设备/时间/状态码）落 DEBUG 日志文件，排查用，不新增 UI。

## 四、功能范围与同步

- **范围**：记账 + 多账号（手机只读）+ **密码门板块（两端，见 §五）**；利润/制作实时行情（kkrb 制造产物/子弹包）不做。
- **方向**：记账数据单向同步（桌面 → 手机）。手机端无任何记账写入路径。
- **触发**：进入页面即拉取 + 切回前台（visibilitychange）自动拉取 + 下拉刷新。不做后台轮询（Chrome 后台冻结 + 电池，且无必要）。
- **离线语义**：离线 = 查看 IndexedDB 缓存快照（历史数据、KPI、图表、密码门快照全可看），不可新增/修改；**首次必须联网打开一次**。
- **数据陈旧认知**：概览页角落 + 设置页显示「上次同步时间」，文案明确「断开连接时显示的是上次同步快照」。
- **版本可见**：设置页显示「客户端版本 vs 服务端版本」，不一致提示刷新（桌面升级后手机刷新即新版）。

## 五、密码门板块（每日地图密码）

**动机**：局内场景——打游戏时不切屏，手机瞄一眼即读当日各图密码。桌面端同步加入作为第三模块（两端同一数据源，手机端为主场景）。

### 5.1 数据事实（2026-08-13 实测）

- **接口**：`POST https://www.kkrb.net/getBonusDoorData`（空 body，需 CSRF 握手——复用 `KkrbClient` 会话/锁/60s TTL 缓存基建）。
- **响应**：`{code: 1, data: {<key>: {password, updated, overridden}}}`；`updated` 为 `YYYYMMDDHHMMSS` 时间戳（密码每日 00:00 轮换）；`overridden` 为后台修正标记（展示层忽略）。
- **地图键 → 中文名**（页面内嵌映射）：`db`零号大坝 / `cgxg`长弓溪谷 / `bks`巴克什 / `htjd`航天基地 / `cxjy`潮汐监狱 / `az3`AZ3 / `az3r6`AZ3彩六联动房。
- **排除策略**：默认剔除 `az3r6`（AZ3 彩六联动房），**两端一致硬排除，不做开关**（保持极简；未来如需恢复显示，改共享获取层一处即可）。

### 5.2 桌面端模块（第三模块）

- **位置**：侧边栏第三导航项「密码门」（记账 / 利润 / 密码门），`QStackedWidget` 第三页。
- **数据**：`kkrb_client.fetch_bonus_door_data()`（新增方法，复用会话/锁/缓存；**单点过滤**——默认剔除 `az3r6`，桌面端 UI 与手机代理端点同源同结果）+ `kkrb_parsing` 纯函数解析 + `kkrb_models` 模型（`BonusDoorItem`）。
- **UI**：网格卡片（跟随利润页视觉语言），每卡：地图名 + 密码大字（**不展示更新时间**，v5 拍板）；遵循主题契约（`apply_theme` 钩子自动纳入 `_theme_refreshers`）。
- **基建复用**：`FetchPageBase` 懒加载状态机 + `FetchWorker` 后台线程 + 错误重试（利润页同款）。
- **测试**：client 方法（FakeOpener 注入既有惯例）+ 解析纯函数 + 页面单测 + 代理端点单测，全部纳入 pytest（覆盖率口径不变）。

### 5.3 手机端 Tab「密码」

- **入口**：底部第 4 Tab（概览 / 明细 / **密码** / 设置）+ **记住上次停留 Tab**（局外最后一次停在密码页，进局后点开 App 直接就是密码页）。
- **UI**：地图卡片列表——每卡：地图名（15px）+ **密码大字（34px/700/tabular-nums，与 KPI 同字号体系）**（**不展示更新时间**，v5 拍板），局内 1 米外扫一眼即读；下拉刷新 + 进入即拉（继承现有同步触发）。
- **数据**：代理端点 `GET /api/kkrb/bonus-door`（透传 client 结果，已过滤）；IndexedDB 缓存当日快照（局域网断线仍可看上次密码）。
- **明确不做**：密码门位置图（webp 图片库）——用户拍板"以后也不做，没必要"。

## 六、数据口径

**原样复用桌面端口径，手机端只呈现、不发明**（保证两端数字永远对得上）：

- 格式化：`presentation` / `formatting` 的 K/M/B、千分位、`¥` 规则；
- 盈亏颜色：红涨绿跌（桌面既定语义）；
- 收益率：`calculator` 的 `format_rate` 单源规则（`+2.4%` / `-1.3%`，1 位小数）；
- 口径：总收益 = warehouse（含现金），现金 ⊆ 仓库；差值 = 当日 warehouse − 前日 warehouse；
- 日期键 `YYYY-MM-DD` **字符串原样展示，禁止 JS `Date` 转换**（时区偏移差一天的坑，红线）；
- 密码门：地图名映射与排除策略单源（§5.1），两端同源。

## 七、UI 信息架构

底部 4 Tab：

| Tab | 内容 |
|---|---|
| **概览** | 顶部账号切换 + 总资产/现金/仓库 3 张 KPI 卡 + 近 30 天趋势图 |
| **明细** | 按日期分组的记录列表：每行 = 日期 + 现金/仓库 + 当日盈亏 Badge（涨跌色）；30 天滚动；按账号过滤；无编辑/删除（只读） |
| **密码** | 当日地图密码卡片列表（§5.3） |
| **设置** | 同步状态（上次同步时间/连接地址）+ 五步诊断清单 + 主题跟随系统 + 关于 |

**记忆**：PWA 记住上次停留 Tab（localStorage/IndexedDB），打开默认回到上次页面。

**趋势图**（SVG 手绘，无图表库）：

- 单图双曲线（现金 + 仓库），默认同轴展示；
- 点图例切换「只看现金 / 只看仓库」（数据量级差 5 倍+，双 Y 轴在小屏不可读）；
- 画线动画（stroke-dashoffset）**仅首次加载与切换账号时播放 400ms**；静默刷新只做整图淡入 150ms，不重播画线。

**账号切换**：顶部下拉（多账号，账号名 = 目录名，需 URL 编码处理中文/空格/emoji）。

## 八、主题与视觉规格（移动化重构）

**原则**：继承桌面两套色板（Sage Ledger 浅色 / Midnight & Amber 暗色）的**色值体系**，但按移动设计重建层级；全量 CSS 变量，**实现禁魔法数字**。

### 色板（CSS 变量，色值取自桌面 theme.py 两套色板）

浅色：`--bg / --card / --text / --text-secondary / --accent / --up(红) / --down(绿) / --border`；
暗色：同键位另一套值。

### 阴影策略（D3 定案）

- **浅色**：双层弱阴影 `0 1px 2px rgba(0,0,0,0.06)` + `0 4px 12px rgba(0,0,0,0.05)`；
- **暗色**：不用阴影（黑底黑影无效），改用 `1px` 边框 + 背景层级差（卡片 `#1E1E1E` / 页面底 `#121212` 之类，取色板值）。

### 字体

```css
--font-stack: "MiSans", -apple-system, "SF Pro Text", "PingFang SC",
              "HarmonyOS Sans SC", "Segoe UI", "Microsoft YaHei", system-ui, sans-serif;
```

- 零 webfont 下载，全设备本机字体；小米 13 Pro 优先命中 MiSans；
- 数字一律 `font-variant-numeric: tabular-nums`（金额刷新不抖、小数点对齐；密码数字同理）；
- 字重只用 400/500/600/700，**禁用 100/200 超细**；
- 字号阶梯（8pt 网格，6 档）：

| 用途 | 字号/字重 |
|---|---|
| KPI 大数字 / 密码大字 | 34px / 700 / tabular-nums |
| 明细金额 | 17px / 600 |
| 页面标题 | 17px / 600 |
| 明细日期/正文/地图名 | 15px / 400–500 |
| 标签 | 13px / 600（Badge 11px） |
| 辅助说明 | 12px / 400（Tab bar 文字 10–11px） |

- 间距网格 `--space-1: 4px` … `--space-6: 32px`；圆角 `--radius: 12px / 16px`。

## 九、动效规格

**原则**：动效只传达"状态变化与层级"，不装饰。三类：转场、反馈、数据更新。

### 全局变量

```css
--dur-fast: 150ms;  --dur-base: 200ms;  --dur-slow: 300ms;
--ease-out: cubic-bezier(0.33, 1, 0.68, 1);   /* easeOutCubic，Apple 系 */
--ease-in:  cubic-bezier(0.55, 0.06, 0.68, 0.19);
```

### 动效清单

| 场景 | 动效 | 时长/曲线 | 触发 |
|---|---|---|---|
| Tab 切换 | 内容区淡入 + 上移 8px | 200ms ease-out | 切 Tab |
| KPI 数字更新 | count-up | 250ms ease-out | 数据到达（跟随桌面端动画语言） |
| 趋势图 | 画线动画（stroke-dashoffset） | 400ms ease-out | **仅首次加载与切换账号** |
| 趋势图静默刷新 | 整图淡入 | 150ms | 后台拉取完成（不播画线） |
| 盈亏 Badge 变色 | 背景色过渡 | 150ms | 值变化 |
| 按钮按压 | scale(0.98) | 100ms | `:active`（触感反馈） |
| 下拉刷新指示 | SVG 圆环旋转 | 1s linear infinite | **全站唯一无限动画** |

**密码门页面**：无专属动效——密码卡仅随 Tab 切换走统一转场；数据更新时密码数字淡入 150ms（不播 count-up，密码是"查值"不是"数值增长"，count-up 语义不符）。

### 禁做清单（动效侧 AI 味，写进验收）

3D 翻转；overshoot 回弹/弹簧曲线（Web 上易廉价）；无限循环（下拉刷新除外）；整屏滑动转场；粒子/光效；Tab bar 滑动指示条；hover 动画（移动端无 hover，不写）。

### 无障碍

`prefers-reduced-motion: reduce` → 全部动效归零（count-up 直接落值、画线直接呈现、无位移），尊重系统「减少动画」设置。

## 十、落地风险对策（调研结论，2026-08-13）

### 外部事实验证（影响设计的 3 条）

1. **Service Worker 在 `http://局域网IP` 下不可注册**（仅 HTTPS / localhost 例外）。SW 是渐进增强，无 SW 页面完全可用。→ 离线不依赖 SW。
2. **无 SW 也能"添加到主屏幕"**——Android Chrome 支持手动把任意网站安装为应用（无需 manifest）。→ 快捷方式可用，浏览器模式（带地址栏）。
3. **IndexedDB 是 best-effort 存储，存储压力下按 LRU 整源清除**。→ 启动时 `navigator.storage.persist()` 申请持久化（Android Chrome 按互动历史自动批准）；数据源在桌面端，被清仅需重扫码重拉，低影响。

### 连接层（最高频故障区）

| 风险 | 对策 |
|---|---|
| 路由器 AP 隔离/访客网络 | 诊断清单第一项；小米路由/光猫一体机常默认开隔离 |
| Windows 防火墙首次弹窗误拒 | 面板提示「首次弹窗请点允许」；诊断清单含防火墙项 |
| 多网卡/虚拟网卡（VMware/Hyper-V/VPN） | 服务绑 0.0.0.0；面板列出全部局域网 IPv4（过滤虚拟网卡/link-local）；二维码用按网关匹配的最优 IP |
| 2.4G/5G 双频跨网段 | 诊断清单；面板显示网段 |
| 桌面休眠 | 诊断清单含「桌面是否开机/未休眠」 |
| DHCP 换 IP | 手机提示重新扫码；桌面端启动 IP 有变则面板提醒 |

**五步诊断清单**（设置页 + 连接失败页内嵌）：① 手机与桌面在同一 WiFi？② 路由器是否开了 AP 隔离/访客网络？③ 桌面防火墙首次弹窗是否点了允许？④ 桌面是否开机未休眠？⑤ 重新扫码。

### 桌面服务端健壮性

| 风险 | 对策 |
|---|---|
| 进程残留占端口（本项目逃生舱同类坑） | 服务线程退出优雅 join + 超时兜底；启动检测端口占用自动换端口 |
| 每请求读盘 IO + 与原子写竞态 | **内存快照 + 版本号**：服务端缓存快照，桌面保存后失效重建；API 返回 `{version, data}`，手机端同版本跳过渲染 |
| 授权弹窗骚扰 | 设备被拒后 30s 静默 |
| 路径穿越（http.server 不自动防） | 固定 API 端点 + 静态文件白名单目录 + 路径规范化 |
| kkrb 请求并发（桌面 UI + 手机代理同时拉） | 共享 `KkrbClient`（已有整体持锁 + 60s TTL 缓存），并发安全既有保障 |

### 手机端浏览器/PWA 层

| 风险 | 对策 |
|---|---|
| SW 不可用（http 局域网） | 离线 = IndexedDB 渲染 + 页面级 HTTP 强缓存（应用壳几十 KB + max-age 一年 + 版本指纹）；首次必须联网 |
| IndexedDB 被 LRU 清除 | `navigator.storage.persist()` 申请持久化 |
| 无痕模式 | IndexedDB 不持久 → 每次重授权；设置页提示一句，不做特殊支持 |
| Chrome 后台冻结 | 已按「回前台即拉」设计；不做后台轮询 |
| MIUI 自带浏览器 vs Chrome | **以 Chrome 为唯一验证基线**；自带浏览器能开能看即可，不保证添加主屏幕/离线 |
| 扫码 URL 带敏感信息 | 二维码仅含 IP:端口；device_id 存 IndexedDB；URL 全程无 token |
| 数据陈旧认知 | 概览角落 + 设置页显示「上次同步时间」 |

### 数据与一致性

| 风险 | 对策 |
|---|---|
| JS Date 时区偏移（日期键被解析差一天） | 日期字符串原样展示，禁止 Date 转换（红线） |
| 账号名含中文/空格/emoji（目录即账号名） | API 参数 encodeURIComponent；服务端路径白名单 |
| 数据量增长 | 账号×30 条上限 → 全量拉取几百 KB；版本号避免重复渲染；不做增量同步 |

### 打包/发布

stdlib 服务零新增依赖、体积不变；桌面升级 → 手机刷新即新版（版本指纹防旧缓存）；设置页两端版本对比。

## 十一、工程约束

- 桌面端零新 Python 依赖（`http.server` 只读 API）；requirements.txt 不变；
- 二维码用浏览器端 JS 生成（connect 页），不引入 Python qrcode/PIL；
- 服务端数据读取走内存快照 + 版本号（见 §十）；
- 静态文件强缓存 + 版本指纹（`?v=` 或文件名 hash）；
- 服务模块单测纳入 pytest（覆盖率口径不变）；PWA 端以 Chrome 手工 + GUI 验证为主（web-gui-tester 流程），JS 测试策略待立项时定；
- 桌面端改造为**新增独立模块**：`kkrb_client.fetch_bonus_door_data()`（+ 解析纯函数 + `BonusDoorItem` 模型）+ 密码门页面（第三页，`FetchPageBase` 基建复用 + `apply_theme` 契约）+ 手机连接服务/面板 + 白名单；**不破坏现有装配/渲染契约（C4）与主题契约（C1）**；
- 服务线程不得阻塞 Qt 事件循环；退出时优雅关闭（逃生舱教训：无界 wait → 进程残留 → 占单实例锁/端口 → 新启动静默退出）。
