# ADR-0005：多账号存储布局

## 决策背景

记账模块为单账号：所有数据固定落在统一数据目录的 data.json，用户无法在同一台
机器上为不同用途（不同游戏角色 / 区服 / 子账本）分别记账，切换账本只能手动
备份文件。新增多账号能力（Y 系列）需确定：账号数据如何布局、如何发现账号、
如何保证既有用户数据平滑迁入且绝不丢失。

## 可选方案

### 方案 A：目录即账号名（accounts/<账号名>/data.json），无元数据文件

账号根目录 `accounts/` 下的每个子目录即一个账号，目录名即账号名；账号发现 =
目录扫描；不引入 accounts.json 元数据文件。

| 优势 | 代价 |
|------|------|
| 零额外文件，账号列表 = 文件系统事实，无状态漂移 | 账号名即目录名，必须 sanitize（禁用 Windows 保留字符） |
| 目录操作天然原子（mkdir） | 重命名 = 目录改名，需同步处理（本功能不做重命名） |
| 每账号独立 data.json，DataStore 路径注入零改造 | — |

### 方案 B：accounts.json 元数据文件 + 随机目录名

账号名与目录名解耦，元数据（账号名 → 目录）存于 accounts.json。

| 优势 | 代价 |
|------|------|
| 账号名可含任意字符 | 元数据文件与文件系统双事实源，损坏/不一致时需恢复策略 |
| 重命名只需改元数据 | 目录扫描与元数据必须对账，复杂度高 |

### 方案 C：单 data.json 按账号分 key

沿用单一 data.json，内部按账号分组。

| 优势 | 代价 |
|------|------|
| 不新增目录 | 全部账号共用一个文件，损坏即全损；备份滚动互相污染 |
| 改动最小 | 无法按账号独立恢复；CSV 导出/隔离无从谈起 |

## 最终选择

✅ **方案 A：目录即账号名，无元数据文件**

## 理由

- 账号列表 = 文件系统事实，杜绝元数据漂移；目录缺失 = 账号不存在，语义天然。
- 每账号复用既有 `DataStore(data_file, backup_file)` 路径注入：原子写 / 损坏恢复 /
  3 份滚动备份全部继承，零改造。
- 目录 mkdir 是文件系统原语，比「写元数据再建目录」的两步操作更接近原子。
- 与 spec「Out of Scope」一致：不引入 accounts.json；Windows 保留设备名
  （CON/NUL 等）不在账号名校验范围内（已知边界，不做扩展）。

## 布局约定

```
~/Delta Force Dashboard/
├── accounts/
│   ├── .migrated_v2          # v2 迁移完成标记（存在即跳过，幂等）
│   ├── 主账号/
│   │   ├── data.json         # 每账号独立数据（滚动备份 data.json.bak*）
│   │   └── data.json.bak*
│   └── 小号/
│       └── data.json
├── data.json                 # 旧布局（v2 迁移复制源，永不自动删除）
└── settings.json             # 含 current_account（重启恢复上次账号）
```

- 账号目录名即账号名；`list_accounts()` = 目录扫描。
- v2 迁移：`accounts/` 不存在 **且** 旧 data.json 存在 → 复制 data.json + 全部
  `data.json.bak*` 到 `accounts/主账号/`，写 `.migrated_v2` 标记；复制非移动，
  永不自动删源（O-22 铁律延续）。
- `resolve_account(current)` 兜底：current 缺失 / 非字符串 / 目录不存在 →
  回退「主账号」；accounts/ 为空 → 自动创建「主账号」空目录。

## 影响

### 正面

- UI 层不接触文件系统：所有账号操作收敛到 `account_store` 业务层
  （AST 断言防复发：UI 层不得拼装账号路径）。
- 利润模块零改动（kkrb.net API 查询无本地持久化，与账号无关）。

### 代价

- 账号名受目录名约束：拒绝空名 / 重名 / 含 `\ / : * ? " < > |` / 首尾空格或点
  （H1 sanitize），由 `validate_account_name` 统一执行。
- 不做账号重命名 / 删除（不存在「删到零账号」高危路径）。
