# ADR-0002: 图表双曲线合并到同一坐标系（双 Y 轴，方案 B）

## 决策背景
现状 `ChartWidget` 是上下两张图、各自独立 Y 轴（仓库价值 / 现金），垂直空间各占一半。
用户希望把两条曲线合并进同一坐标系。合并存在多个方向性方案，属「设计方向性」决策，
按 O-C2「评审×原型双驱动」规则：先用原型亲手推一遍再拍板（UI 分支适配 PySide6，
QComboBox + QStackedWidget 切变体），本 ADR 记录验证结论。

## 可选方案
1. **方案 A 共享单轴**：两条线共用一个左 Y 轴。
   - 优势：实现最简单（改现有单轴代码的加法）。
   - 代价：现金量级仅仓库约 5%（实测 ¥6 万 vs ¥1.15M，~20 倍差），共享 Y 范围被仓库
     跨度主导，现金被压成底部直线——原型像素验证现金线仅 **16px** 高，趋势不可见。
     且现金⊆仓库（总收益=warehouse 含 cash），「子项与母项同轴比较」本身有视觉误导风险。
2. **方案 B 双 Y 轴**：仓库左轴 / 现金右轴，各自独立量纲（副 ViewBox + `setXLink` +
   `linkToView`）。
   - 优势：唯一「两线都清晰且保留绝对值」的方案（原型验证两条线均占满图高）；
     pyqtgraph 双轴是官方示例同款成熟模式，实现风险可控；保留端点数值标注与 hover 双值。
   - 代价：跨轴高度不可比（同线段长度含义不同，交点/高低是假象）；右轴刻度必须与
     现金曲线同色否则误读归属；窗口 resize 时副 ViewBox 须跟随主 ViewBox
     （`sigResized → linkedViewChanged`），漏一步两线 x 错位——这是隐藏坑位。
3. **方案 C 归一化**：双双指数化到基准 100，只看趋势形状。
   - 优势：零缩放问题，曲线占满图高。
   - 代价：绝对值消失（¥10→12 与 ¥1M→1.2M 高度一样）；首日=0 或负值会除零/指数失真。

## 最终选择
✅ **方案 B（双 Y 轴）**

## 理由
- 用户目标是「两条曲线放一起看趋势」，B 是唯一两线清晰且不丢绝对值的方案（原型像素
  级验证：A 现金线 16px 高、B 两线占满）。
- 现金⊆仓库（子项与母项同轴比较有误导），B 的独立轴弱化该误导；C 归一化过度（丢绝对值）。
- 双 Y 轴是 pyqtgraph 成熟模式（官方 dual-axis 示例同款 ViewBox+linkToView），
  隐藏坑位（resize 同步、右轴同色、跨轴不可比）在原型中已逐一识别并验证。

## 影响
- 正面：单坐标系一眼看两线趋势与量级；UI 垂直空间利用率翻倍（双图各半 → 合并全高）；
  端点标注 / hover 双值 / PNG 导出 / 主题切换能力全部保留。
- 代价：跨轴高度不可比（新增 hover 时仅显示数值不比较线段长度，规避误读）；
  右轴刻度与现金曲线同色；`resizeEvent` 同步逻辑是长期维护坑位，已固化在 `_sync` 闭包内。
- 产品语义提醒：现金是仓库子项，若日后要表达「现金占比」应换归一化或双图，
  勿在双轴坐标系下比较线段高度。

## 原型与验证
- 原型：`app/chart_merge_prototype.py`（A 单轴 / B 双轴 / C 归一化 + 现状基准 4 视图），
  QComboBox 切换，控制台打印各方案已知 bug。
- 留存：throwaway 分支 `prototype/chart-merge`（提交 `b6800bb`），主分支不保留原型文件。
- 验证：offscreen 渲染 4 视图 + PIL 像素级色块扫描（amber/teal 曲线包围盒）——
  A 现金线 y∈[776,792]（16px）、B 两线均占满 y∈[60,892]、C 无绝对值；与预测 bug 一一对应。
